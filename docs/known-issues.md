# Известные проблемы

## ✅ Исправлено: fmp-gamemode не стартовал на Windows из-за better-sqlite3

**Статус:** исправлено 2026-11-08. `fmp-gamemode/src/server/database.ts` переведён на встроенный `node:sqlite`, зависимость `better-sqlite3` удалена. Подробности в [resources/fmp-gamemode.md](resources/fmp-gamemode.md).
Если ошибка снова появится после обновления релиза FMP (новый gamemode из архива перезапишет наш), повтори перевод или возьми `database.ts` из git.

**Симптом** в `server/logs/framework.log`:
```
Failed to start resource fmp-gamemode: Error: A dynamic link library (DLL) initialization routine failed.
...\fmp-gamemode\node_modules\better-sqlite3\build\Release\better_sqlite3.node
```
Без gamemode сервер запускается, но не отвечает на чат-команды и не пускает игроков дальше логина.

**Причина.** Стандартный gamemode хранит аккаунты в SQLite через нативный модуль `better-sqlite3`.
- `npm ci` пытается собрать модуль из исходников и падает без Visual Studio Build Tools.
- У `better-sqlite3` 13.x нет готовых бинарников под Node 25: сервер встраивает Node 25.6.1, ABI 141.
- Готовый бинарник 12.11.1 под ABI 141 скачивается, но внутри `FMPServer.exe` не загружается. Нативные модули Windows ищут функции Node в `node.exe`, а у FMP они лежат в `libnode.dll`.

**Решение.** Не использовать нативные модули Node в ресурсах на Windows-сервере. Для SQLite есть встроенный `node:sqlite` (`DatabaseSync`).

**Как проверить, что исправлено:** в логе есть `Started JS resource: fmp-gamemode` и нет `Failed to start resource fmp-gamemode`.

## FMPServer.exe закрывается сразу после запуска

**Симптом:** окно консоли закрывается примерно через секунду, в `server/logs/` ничего нового не появляется. Код выхода `0xC0000409`. Если вывод перенаправлен в файл, последняя строка: `[World] World at 12.00h, ...`.

**Причина.** Если в `server.json` пустой `mod.game_data_path`, сервер сам ищет игру через реестр (`HKLM\SOFTWARE\WOW6432Node\Bethesda Softworks\Fallout4` → `Installed Path`). Когда там остался путь от старой установки, а диск или папка по этому пути отвечает ошибкой (битая ссылка, отключённый диск: «A device which does not exist was specified»), сервер падает. Просто отсутствующую папку он переживает, а такую ошибку нет.

**Решение.** Всегда указывать `mod.game_data_path` явно, а не оставлять пустым:
- без игры подойдёт `"game-data"`, относительный путь от папки `server/` (так сделано в `server.example.json`). Папки может не быть;
- с игрой нужен путь к её `Data`, например `"D:\\SteamLibrary\\steamapps\\common\\Fallout 4\\Data"`.

**Как проверить:** сервер не закрывается, в логе есть `[GameData] ... No Fallout4.esm in game-data` и `FMP Server successfully started`.

## Ресурсы не грузятся, если в пути к серверу есть кириллица

**Симптом:** `Failed to start resource ...: Cannot find module 'C:/Users/пїЅпїЅпїЅ.../dist/server/index.js'`.

**Причина:** сервер искажает не-ASCII символы в пути к ресурсам. Например, профиль Windows с кириллическим именем (`C:\Users\Ярослав\...`) превращается в `пїЅпїЅпїЅ`.

Часто встречается при имени пользователя Windows на кириллице («Пользователь», «Ярослав»), если сервер лежит на рабочем столе, в «Документах» или «Загрузках».

**Решение:** физически перенести папку туда, где весь путь латинский, например `C:\fo4-server`.
- `subst` и junction (`mklink /J`) **не помогают**: сервер раскрывает их обратно в настоящий путь с кириллицей. Проверено 2026-11-08.
- `start-server.cmd` в корне репо проверяет путь перед запуском и при кириллице выводит понятную ошибку, а не запускает сервер со сломанными ресурсами.

## Игрок не может войти: "Cannot stage the assets"

**Симптом** в `client\logs\FMP.log` у игрока:
```
[StreamedAssets] [error] Cannot stage the assets of 'fmp-asset-demo' in 'FMP\mounted\fmp-asset-demo.stream.…'
[Session] [error] Giving up on the join: ...
```
В логе сервера: `sending resource list`, затем сразу `Disconnecting peer …, reason: 1`.

**Причина:** клиент не смог разложить стримящиеся ассеты (текстуры, `.esp`) ресурса в папку `FMP\mounted`. Точная причина пока не выяснена. Подозрения: кириллица в пути к клиенту или игре, либо нет прав на запись, если игра стоит в `Program Files`.

**Что сделано (2026-11-08):** демо-ресурс `fmp-asset-demo` убран с сервера. Он только демонстрировал стриминг ассетов, для игры не нужен. Других ресурсов со стриминговыми ассетами пока нет, поэтому вход больше на этом не ломается.

**2026-11-09, мод RP_Pipboy:** та же ошибка у того же тестера, когда в `fmp-gamemode` лежит `mods/`. Сервер пакет собирает без ошибок (`Asset pak 'fmp-gamemode' mods: … (built)`, проверено), ломается раскладка на клиенте. Главное подозрение — кириллица в имени пользователя Windows: в его логе путь `C:\Users\…\AppData\Roaming\MafiaHubIntegration` напечатан пробелами. Проверки:
- запуск FMP от администратора;
- `set APPDATA=F:\fmp-appdata` перед запуском `FMPLauncher.exe` из того же `cmd`;
- другая учётная запись Windows с латинским именем.

Чтобы отделить мод от компьютера, есть пустой тестовый плагин `mods-src/test/RP_Test.esp` (только заголовок): положи его в `mods/` один.

**Когда понадобятся свои ассеты** (папки `stream/` и `mods/` в ресурсе), сначала проверь на клиенте:
1. путь к `client\` и к игре латинский;
2. у игрока есть права на запись в папку игры и в папку клиента;
3. после правок лог клиента не содержит `Cannot stage the assets`.

## Силовая броня выглядит искажённой, как обычная броня

**Симптом:** при входе в силовую броню модель игрока сильно искажается и выглядит как обычная броня.

**Что известно (2026-11-08):** gamemode при входе в броню ничего не делает, только пишет в лог (`src/server/powerarmor.ts`). Значит, это, скорее всего, синхронизация брони в самом клиенте FMP. Исправлен один путь, который мог давать такой же эффект после смерти или перезахода: модуль экипировки больше не запоминает и не надевает части силовой брони.

**Что собрать для разбора или для отчёта в Discord FMP:**
1. Кто видит искажение: сам игрок, другие игроки или оба.
2. Как зашли в броню: через рамку в мире или через `/pa`.
3. `client\logs\FMP.log` того, кто видит искажение, и строки сервера `got into power armor (frame …)`.
4. Скриншот.

## Умер с оружием в руках: у других встал, у себя лежит

**Симптом:** после смерти с оружием в руках игрок возрождается для сервера и других игроков, а на его собственном экране персонаж остаётся лежать.

**Причина (2026-11-09), в клиенте FMP 0.2.5.** Лог `client\logs\FMP.log` игрока:
```
Graph event 'WeaponRagdoll' refused while down
Respawn: body at (...), target (...), moved false, GetUpBegin accepted false
```
Пока игрок мёртв, FMP отклоняет событие анимации `WeaponRagdoll`, а при возрождении анимация не принимает команду подъёма `GetUpBegin`. Камеру, стойку и выдачу оружия проверяли: они ни при чём.

**Обход в gamemode:** после такого возрождения сервер ненадолго ставит игроку паралич (`Paralysis`; имя FMP может не знать, тогда используется form ID `0x2F2`), и игра сама роняет и поднимает персонажа. Вручную то же делает `/unstuck`. Подробности и строки лога в [resources/fmp-gamemode.md](resources/fmp-gamemode.md).

**Для отчёта в Discord FMP:** строки выше из `FMP.log`, версия клиента `0.2.5`, условие: смерть с оружием в руках.

## Удар кулаками: урон есть, анимации нет

**Симптом:** удар кулаком наносит урон, но анимации удара не видно.

**Что известно (2026-11-08):** у сервера нет события «замах» или «удар», только «попадание» (`playerHit`). Анимации атак синхронизирует сам клиент FMP, gamemode в это не вмешивается. Исправить из gamemode нельзя, кроме обходного варианта: проигрывать анимацию `playIdle` при попадании. Но тогда она будет запаздывать и появляться только при попадании, а не при каждом замахе.

**Что собрать:** видит ли анимацию сам бьющий или нет её только у других; с оружием ближнего боя (нож, бита) анимация есть? Затем сообщить в Discord FMP с версией клиента (`0.2.5`).

## NPC не синхронизируются

**Симптом:** `No Fallout4.esm in ...\Fallout 4\Data. NPCs are not synced`.

**Причина:** серверу нужна папка `Data` из Fallout 4, а распространять её нельзя.

**Обход:** укажи в `server.json` путь в `mod.game_data_path`. Без этого сервер работает, игроки подключаются, но NPC не синхронизируются.

## "Server tick took N ms against a 17 ms budget" при старте

В первые секунды после запуска это нормально: идёт загрузка ресурсов. Если предупреждение повторяется при работающем сервере, нужно искать, какой ресурс тормозит.
