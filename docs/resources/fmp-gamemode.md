# fmp-gamemode

**Папка:** `server/fmp-resources/fmp-gamemode`
**Статус:** стандартный gamemode из релиза FMP (`@falloutmp/types` 0.2.5) с нашей правкой хранилища

## Что делает

Базовый roleplay-режим от MafiaHub: регистрация и логин через окно CEF поверх кинематографической камеры, создание персонажа, сохранение позиции и состояния, ранги администрации, чат-команды (`/help`, `/tp`, `/give`, `/pa`, `/time`, `/weather`, `/mines` и др.).

## Наши изменения относительно релиза

| Файл | Изменение | Зачем |
|---|---|---|
| `src/shared/auth.ts`, `src/server/accounts.ts`, `ui/login/index.html` | аккаунт = Username из формы, а не ник лаунчера; вкладки Log in / Create account; имя и фамилия персонажа отдельными полями; запрет двойного входа | все без ника попадали в один аккаунт `Player` |

| `src/server/respawn.ts` (новый), `index.ts` | возрождение с повторами, поиск «застрявших» мёртвых, `/revive` | игроки иногда не возрождались после смерти |
| `src/server/equipment.ts` (новый), `accounts.ts`, `respawn.ts`, `database.ts` (миграция 5) | экипировка (оружие в руках, надетая броня) сохраняется и возвращается после смерти и при входе | после смерти и перезахода всё оказывалось в инвентаре |
| `src/server/emotes.ts`, `src/client/emotes.ts`, `ui/emotes/`, `emotes.json` (новые) | колесо эмоций на P и `/emote` через `playIdle` | FMP не синхронизирует большинство анимаций; анимации, запущенные сервером, видят все |

| `package.json` | удалены `better-sqlite3` и `@types/better-sqlite3`, добавлен `@types/node` 25.9.9 (сервер работает на Node 25.6.1) | то же |

Схема БД та же, поэтому файл `gamemode.sqlite` совместим в обе стороны.

**При обновлении релиза FMP** не перезаписывай эту папку вслепую. Сначала сравни новый gamemode из архива с нашим через `git diff`, потом перенеси правки.

## Хранилище

- Файл: `server/fmp-data/gamemode.sqlite`, путь отсчитывается от рабочей папки сервера. Используется режим WAL, поэтому рядом лежат `-wal` и `-shm`.
- Миграции схемы хранятся в массиве `kMigrations`; номер применённой версии записан в `PRAGMA user_version`. Новую миграцию добавляй только в конец массива.
- Создание аккаунта вместе с персонажем идёт одной транзакцией: если имя персонажа занято, аккаунт тоже не создаётся.

## Username и имя персонажа

Аккаунт — это **Username, который игрок вводит в окне логина**. Ник из лаунчера на аккаунт не влияет (изменено 2026-11-08). Раньше аккаунт брался из ника, и все, кто не задал ник, попадали в один аккаунт `Player` с одним персонажем.

| | Где вводится | Правила | Где используется |
|---|---|---|---|
| **Username** | окно логина, оба режима | 3–20 символов: латиница, цифры, `_`; уникален без учёта регистра; `Player` запрещён | вход (пароль привязан к нему), `setadmin`, `deleteaccount`, OOC-чат, чат персонала, логи |
| **Имя персонажа** | окно логина, «Create account»: поля First name и Last name | каждое 2–16 латинских букв; регистр исправляется сам; уникально | ник над головой, имя в чате, `/me`, `/do`, поиск игрока в командах |

Окно логина на русском (с 2026-11-08). Сообщения об ошибках входа и причины кика при логине тоже на русском, логи сервера остаются на английском.

Окно логина: вкладки **Вход** (логин + пароль) и **Регистрация** (Username, пароль, подтверждение, имя и фамилия персонажа). Ник из лаунчера, если он задан и это не `Player`, подставляется в поле Username.

**Один аккаунт — один игрок одновременно.** Попытка войти в аккаунт, который уже в игре, отклоняется ошибкой `<username> is already in the game`, в логе сервера появляется `second login ... refused`.

## Админы и ранги

Ранг хранится в аккаунте, в базе `fmp-data/gamemode.sqlite`, и выдаётся **по Username**.

| Ранг | Число | Что даёт |
|---|---|---|
| `player` | 0 | `/help`, `/char`, `/emote`, RP-чат: `/me`, `/do`, `/s`, `/b`, `/ooc`, `/pm`, `/pay` |
| `moderator` | 1 | + `/a` (чат персонала), `/kick`, `/goto`, `/gethere`, `/revive` |
| `admin` | 2 | + `/emote test`, `/emote try`, `/emote add`, `/emote remove`, `/tp`, `/give`, `/time`, `/timescale`, `/weather`, `/pa`, `/xp`, `/level`, `/perk`, `/special`, `/value`, `/caps`, `/look`, `/outfit`, `/kill`, `/fire`, `/items`, `/mines` |
| `owner` | 3 | + `/setadmin` (выдавать ранги из игры) |

### Как назначить первого админа
1. Игрок заходит на сервер и в окне логина выбирает **Create account**: Username (например `yaroslav_99`), пароль, имя и фамилия персонажа.
2. В **консоли сервера**:
   ```
   setadmin yaroslav_99 owner
   ```
   **Ожидается:** `yaroslav_99 is now owner`. Если игрок онлайн, ранг работает сразу.
   Ответ `No account named …` значит, что Username введён неверно: его можно посмотреть в логе по строке `registered as <username> / <персонаж>`.
3. Дальше owner выдаёт ранги из игры: `/setadmin <username> <ранг>`.

**Проверка:** в игре `/help` показывает `Commands (owner): …`.

### Удалить аккаунт или сбросить профиль
В консоли сервера:
```
deleteaccount <username>
```
Удаляет аккаунт и его персонажа (внешность, позицию, инвентарь, прогресс). Username и имя персонажа освобождаются. Если игрок онлайн, его выкидывает с сообщением `Your account was deleted`, без сохранения.
**Ожидается:** `Deleted account <username> and its character <имя>`.

Сбросить всех сразу: остановить сервер и удалить `server\fmp-data\` (файлы `gamemode.sqlite`, `-wal`, `-shm`).

### Как проверить исправление с двумя игроками в одной сети
1. Оба заходят на сервер; ник в лаунчере у обоих может быть `Player`.
2. Каждый выбирает **Create account** со своим Username и своим персонажем.
   **Ожидается:** у каждого свой персонаж, в логе две строки `registered as …` с разными Username.
3. Второй игрок пытается войти в аккаунт первого (вкладка Log in, Username первого, верный пароль).
   **Ожидается:** ошибка `… is already in the game`.
4. `/ooc привет` от каждого: в чате видны разные Username, а не `Player`.

## Смерть и возрождение

Через 5 секунд после смерти игрок возрождается там, где упал (`src/server/respawn.ts`).

Раньше gamemode вызывал `respawn()` один раз, и если команда терялась, игрок оставался лежать навсегда (баг от 2026-11-08). Теперь:
- после `respawn()` сервер каждые 2 секунды проверяет, встал ли игрок, и повторяет, до 10 попыток;
- раз в 10 секунд и сразу после старта gamemode сервер ищет мёртвых игроков, для которых возрождение не запланировано (например, умер во время `ensure fmp-gamemode`), и поднимает их;
- если 10 попыток не помогли, игроку приходит сообщение в чат, а в лог пишется ошибка;
- **`/revive <игрок>`** (moderator+) поднимает вручную; игрок ищется по имени персонажа или id.

**Рассинхрон «сервер считает живым, игра показывает мёртвым».** `respawn()` ничего не делает с игроком, которого сервер считает живым, поэтому за этим следит клиентская часть (`src/client/life.ts`):
- если игра показывает игрока мёртвым дольше 12 секунд, клиент каждые 5 секунд сообщает серверу (`rp:life:stuck`) и пишет в `client\logs\FMP.log` строки с `[life]`;
- если сервер согласен, что игрок мёртв, он запускает возрождение, если оно ещё не идёт;
- если сервер считает игрока живым, он действует по шагам: **1)** переставляет игрока на то же место; **2–3)** проводит через смерть заново (`health = 0`), после чего срабатывает обычное возрождение; **дальше** просит перезайти, один раз.

**Что смотреть в логе сервера, если кто-то снова «завис»:**

| Строка | Значит |
|---|---|
| `<username> died` / `<a> killed <b>` | смерть получена |
| `still down: respawn attempt N/10` | игра не применила возрождение, сервер повторяет |
| `is up after N respawn attempts` | встал со N-й попытки |
| `found down with no respawn pending` | смерть прошла мимо gamemode, сервер подхватил |
| `their game shows them dead for N s but the server has them up; recovery step K/3` | рассинхрон: игра показывает мёртвым, сервер считает живым; идёт восстановление |
| `their game has them standing; equipment goes back on` | игра игрока подтвердила подъём, экипировка возвращается |
| `still shown dead after 3 recovery steps` | не помогло; нужен `client\logs\FMP.log` игрока (строки `[life]`) |
| `still down after 10 respawn attempts` | не помогло; пришли этот кусок лога и `client\logs\FMP.log` игрока |

**Как проверить:**
1. В игре (admin) выполни `/kill`. **Ожидается:** в логе `<username> died`, через ~5 секунд игрок встаёт; строк `still down` нет или их немного.
2. Убей себя через `/kill` и сразу выполни в консоли сервера `ensure fmp-gamemode`. **Ожидается:** в течение 10 секунд `found down with no respawn pending; respawning`, игрок встаёт.
3. Модератор: `/revive <имя>` на живом игроке отвечает `… is not down`.

## Экипировка после смерти и входа

В сохранении персонажа (`CharacterDocument`) есть только инвентарь, без пометки, что надето. Поэтому раньше после смерти и при каждом входе оружие и броня оказывались в инвентаре. Теперь (`src/server/equipment.ts`):
- пока игрок жив и залогинен, сервер раз в 5 секунд запоминает оружие в руках и надетую броню;
- после возрождения запомненное надевается обратно, оружие возвращается в руки. **Только после того, как игра игрока сама сообщит, что персонаж встал** (`localPlayerRespawn` → `rp:life:up`), и ещё через 1 секунду. Раньше оружие выдавалось, как только сервер видел игрока живым, то есть во время подъёма, и игрок с оружием в руках оставался лежать (баг от 2026-11-08). От смерти до этого сообщения экипировка не запоминается заново, максимум 60 секунд, чтобы не затереть оружие пустыми руками;
- при каждом сохранении экипировка пишется в базу (колонка `characters.equipment`, миграция 5), при входе надевается снова;
- то, чего больше нет в инвентаре (продал, выбросил), пропускается; в логе: `<ник>: login: not carried any more, left off: …`;
- через 3 секунды сервер проверяет, что оружие в руках, и при необходимости просит ещё раз (`weapon … not in hands yet; asking again`).

**Силовая броня не трогается:** пока игрок в ней, экипировка не запоминается и ничего не надевается. В броне `getOutfit()` возвращает её части, и если надеть их как одежду, модель искажается.

Ограничения: модификации оружия при перезаходе не сохраняются, потому что инвентарь хранит только «предмет × количество». Оружие возвращается в руки **обнажённым**, так работает `equipItem`.

**Как проверить:**
1. Возьми оружие в руки, надень броню. Подожди 5 секунд, выполни `/kill`.
   **Ожидается:** через ~6–8 секунд игрок встаёт с тем же оружием в руках и в той же броне.
2. Выйди из игры и зайди снова.
   **Ожидается:** после логина оружие в руках, броня надета.
3. Сними всю броню и убери оружие, подожди 5 секунд, перезайди.
   **Ожидается:** ничего не надевается: «пустое» тоже запоминается.

## Эмоции: колесо на P

FMP 0.2.5 не синхронизирует большинство анимаций между игроками (см. [known-issues.md](../known-issues.md)). Анимации (idle), которые запускает сервер (`Player.playIdle`), видят все игроки рядом. На этом построены эмоции.

- **P** открывает колесо. Клик по сегменту проигрывает эмоцию, центр «Стоп» возвращает в обычную стойку, **P**, **Esc** или правая кнопка мыши закрывают колесо. Колесо открывается только после входа в аккаунт и не открывается, пока игрок мёртв.
- Запасной вариант через чат: `/emote` показывает список, `/emote <имя>` проигрывает, `/emote stop` останавливает.
- Не чаще одной эмоции в 0,8 секунды на игрока.

### Список эмоций: `emotes.json`
Лежит в `server/fmp-resources/fmp-gamemode/emotes.json`:
```json
{
  "salute": { "idle": "Salute", "label": "Отдать честь" },
  "_candidates": ["IdleWave", "IdleClapping", "..."]
}
```
- ключ: имя эмоции, от 1 до 24 символов `a-z 0-9 _ -`; `idle`: **EditorID** анимации (IDLE-запись из `Fallout4.esm`); `label`: подпись в колесе;
- `_candidates`: EditorID, которые **ещё не проверены**. Это предположения, в колесе их нет.

Проверенное имя пока одно, `Salute`, его называет документация API FMP. Остальные проверяются в игре, сервер с данными игры (`mod.game_data_path`) сразу отклоняет несуществующие.

### Добавление эмоций из игры (admin+, без сборки и перезагрузки)
| Команда | Что делает |
|---|---|
| `/emote test` | проигрывает следующего кандидата из `_candidates`: `Кандидат 3/40: IdleX, отправлено` или `такой анимации нет` |
| `/emote test <номер>` | конкретный кандидат по номеру |
| `/emote try <EditorID>` | любой EditorID, например найденный в FO4Edit |
| `/emote add <имя> <EditorID> <подпись>` | добавляет в колесо всем сразу и записывает в `emotes.json`; несуществующий EditorID не примет |
| `/emote remove <имя>` | убирает из колеса |

Порядок: `/emote test` несколько раз. Если сервер ответил «отправлено» и второй игрок рядом видит позу, выполни `/emote add wave IdleWave Помахать`.

Свои EditorID можно найти в **FO4Edit (xEdit)**: `Fallout4.esm` → `Idle Animation`. Сидячие анимации без мебели не работают.

`/emote add` и `/emote remove` меняют `emotes.json` на сервере. Закоммить его, иначе следующий `git pull` с ним конфликтнёт.

Если файл правили вручную, выполни `ensure fmp-gamemode`. Игрокам после этого придётся войти заново.

### Если колесо не открывается
В `client\logs\FMP.log` игрока ищи строки `[emotes]`:
| Строка | Значит |
|---|---|
| `key P bound to the wheel` | клавиша назначена; если строки нет, клиентская часть gamemode не загрузилась |
| `wheel view N created` / `wheel page loaded` | страница колеса создана и загрузилась |
| `P ignored: not logged in` | P нажали до входа в аккаунт |
| `opening the wheel (N emote(s))` | P нажата и колесо открывается; если его не видно, пришли лог |
| `could not create the wheel` | ошибка создания страницы, текст ошибки в той же строке |

**Как проверить:**
1. Войди в игру и нажми P. **Ожидается:** колесо с «Отдать честь» и «Стоп» в центре.
2. Кликни «Отдать честь». **Ожидается:** персонаж отдаёт честь, второй игрок рядом это видит.
3. Нажми P и кликни «Стоп» во время анимации. **Ожидается:** персонаж возвращается в стойку.
4. До входа в аккаунт P ничего не делает.

## Как проверить

### Без игры (только сервер)
1. Запусти `server\FMPServer.exe`.
   **Ожидается** в логе:
   ```
   [fmp-gamemode] database fmp-data/gamemode.sqlite at schema 5
   Started JS resource: fmp-gamemode
   ```
   и **нет** строки `Failed to start resource fmp-gamemode`.
2. Введи в консоли `setadmin nobody 1`.
   **Ожидается:** `[fmp-gamemode] No account named nobody`. Это значит, что запрос к БД выполнился.
3. Должен появиться файл `server\fmp-data\gamemode.sqlite`.

Проверено 2026-11-08: сервер запускался с gamemode, кроме того, скомпилированный `database.js` прогнан отдельным скриптом на временной БД. Скрипт проверил создание и поиск аккаунта, откат транзакции при занятом имени персонажа, `setAdminLevel`, сохранение и чтение персонажа, `COALESCE` для документа персонажа.

### С клиентом Fallout 4
1. Подключись к серверу. **Ожидается:** окно логина поверх пролёта камеры.
2. Зарегистрируйся (пароль и имя персонажа), пройди создание персонажа.
3. Перейди в другое место, выйди и зайди снова с тем же паролем.
   **Ожидается:** логин принят, персонаж появляется там, где вышел, с той же внешностью.
4. В консоли сервера выполни `setadmin <твой ник> 3`, затем в игре `/help`.
   **Ожидается:** в списке появились админские команды.

## Известные ограничения
- `node:sqlite` в Node 25 ещё помечен как release candidate. API стабильный, но при обновлении релиза FMP со сменой версии Node стоит пройти проверку выше заново.
