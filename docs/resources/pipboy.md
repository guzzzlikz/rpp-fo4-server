# Модульный Pip-Boy

Часть ресурса `fmp-gamemode`. Что персонаж может использовать — HUD, V.A.T.S., экраны Pip-Boy, голозаписи — зависит от устройств, которые он носит в инвентаре. Решает только сервер, клиент лишь применяет решение.

| Файл | Что в нём |
|---|---|
| `server/fmp-resources/fmp-gamemode/pipboy.json` | настройки: устройства, что они дают, какие меню закрывать |
| `src/server/pipboy.ts` | расчёт возможностей, база, команды, трещина от взрыва |
| `src/client/pipboy.ts` | применение в игре: HUD, закрытие меню |
| `src/shared/pipboy.ts` | флаги возможностей и формат сообщения сервер → клиент |
| `src/server/database.ts` | таблица `pipboy` (схема 6) |

## Как это работает

1. Игрок входит в аккаунт и появляется в мире.
2. Сервер смотрит **свою** запись инвентаря игрока и находит в ней устройства из `pipboy.json`.
3. Сервер складывает, что дают эти устройства, добавляет базовый набор (`noDeviceMask`) и выданное персоналом, затем вычитает отнятое. Треснувший Pip-Boy считается не носимым.
4. Результат (маска возможностей) уходит на клиент игрока.
5. Клиент закрывает меню без нужной возможности в момент открытия и, пока доступ запрещён, раз в 100 мс проверяет, не открылось ли оно снова (иначе частые нажатия Tab или Q проскакивают). HUD по умолчанию остаётся как в обычной игре. Только с `"hideHud": true` клиент примерно через секунду после входа прячет весь HUD, если в маске нет ни компаса, ни счётчика Гейгера, ни биомонитора.
6. Маска пересчитывается, когда меняется инвентарь (подобрал, выбросил, купил), раз в 10 секунд (на случай, если предмет выдал скрипт) и после каждой команды персонала. Клиенту она отправляется, только если изменилась.

Формула:

```
маска = (устройства | noDeviceMask | выдано) & ~отнято
```

Выданное, отнятое и трещина хранятся в SQLite и переживают перезаход и перезапуск сервера. Сами устройства не хранятся: их каждый раз заново находят в инвентаре.

## Возможности

| Имя | Флаг | Что даёт в игре сейчас |
|---|---|---|
| `compass` | `0x0001` | HUD при `hideHud` |
| `geiger` | `0x0002` | HUD при `hideHud` |
| `biomonitor` | `0x0004` | HUD при `hideHud`; экран Pip-Boy в строгом режиме |
| `map` | `0x0008` | экран Pip-Boy в строгом режиме |
| `gps` | `0x0010` | экран Pip-Boy в строгом режиме |
| `radio` | `0x0020` | экран Pip-Boy в строгом режиме |
| `flashlight` | `0x0040` | пока ничего: фонарик через FMP не заблокировать |
| `vats` | `0x0080` | открытие V.A.T.S. (`VATSMenu`) |
| `holotape` | `0x0100` | меню голозаписей, если вписать его в `blockedMenus` |
| `full` | `0xFFFF` | всё |
| `none` | `0` | ничего |

В командах и в `pipboy.json` возможности пишутся именами (`vats`, `map`) или числом (`0x0081`).

## Настройки: `pipboy.json`

Лежит в `server/fmp-resources/fmp-gamemode/`. После правки введи в консоли сервера `pipboy reload`: настройки перечитаются, маски игроков в сети пересчитаются, перезапуск не нужен. Если файл не читается (нет его или ошибка в JSON), модуль выключен, и у всех всё доступно.

```json
{
  "enabled": true,
  "noDeviceMask": "none",
  "devices": [
    { "form": "0x00021B3B", "label": "Pip-Boy 3000 Mk IV", "caps": ["full"], "wrist": true }
  ],
  "crackOnBlastDamage": 0,
  "blockedMenus": {
    "VATSMenu": "vats"
  },
  "strictPipboyMenu": false,
  "hideHud": false
}
```

| Поле | По умолчанию | Что значит |
|---|---|---|
| `enabled` | `true` | `false` выключает модуль: у всех всё доступно, клиент ничего не прячет |
| `noDeviceMask` | `"none"` | что есть у каждого даже без устройств, например `["vats"]` |
| `devices` | Pip-Boy | список устройств, см. ниже |
| `crackOnBlastDamage` | `0` | урон от взрыва, при котором Pip-Boy трескается; `0` — никогда |
| `blockedMenus` | `VATSMenu` | меню игры и возможность, без которой оно закрывается |
| `strictPipboyMenu` | `false` | `true`: Pip-Boy (Tab) не открывается совсем без `map`, `radio`, `biomonitor` или `gps` |
| `hideHud` | `false` | `true`: без `compass`, `geiger` и `biomonitor` прячется **весь** HUD, включая прицел, патроны и уведомления. `false`: HUD как в обычной игре |

### Устройства

```json
{ "form": "0x00021B3B", "label": "Pip-Boy 3000 Mk IV", "caps": ["full"], "wrist": true }
```

- `form` — form ID предмета в hex. Узнать его можно в консоли игры: `help <часть названия> 4`.
- `label` — название для команд и логов.
- `caps` — что даёт устройство: одно имя, список имён или число.
- `wrist` — носится на руке: трещина выводит его из строя. Ставь только Pip-Boy и похожим.

Устройство «носится», если оно есть в инвентаре. Надетым оно быть не обязано.

В обычном Fallout 4 нет компаса, дозиметра или биомонитора как отдельных предметов. Для них нужны предметы из мода или подходящие обычные предметы. Пример набора на обычных предметах:

```json
"devices": [
  { "form": "0x00021B3B", "label": "Pip-Boy 3000 Mk IV", "caps": ["full"], "wrist": true },
  { "form": "0x000xxxxx", "label": "Компас",            "caps": ["compass"] },
  { "form": "0x000xxxxx", "label": "Дозиметр",          "caps": ["geiger"] },
  { "form": "0x000xxxxx", "label": "Тактический КПК",    "caps": ["map", "gps", "radio"] }
]
```

Вместо `0x000xxxxx` подставь реальные form ID. Ошибки в файле пишутся в лог сервера строками `pipboy.json: …`, при этом неверное устройство пропускается, а остальные работают.

### Готовые варианты

| Чего хочешь | Что поставить |
|---|---|
| Всё закрыто, открывают только устройства (сейчас) | `"enabled": true`, `"noDeviceMask": "none"` |
| HUD у всех, V.A.T.S. только с Pip-Boy (сейчас) | `"hideHud": false` |
| Без устройства нет вообще никакого HUD | `"hideHud": true` |
| Pip-Boy ничего не даёт, только особые предметы | убрать Pip-Boy из `devices` |
| Без Pip-Boy нельзя открыть его экран | `"strictPipboyMenu": true` |
| Pip-Boy ломается от гранат | `"crackOnBlastDamage": 30` (подбери порог) |
| Модуль не нужен | `"enabled": false` |

## Команды

### В чате

| Команда | Кто | Что делает |
|---|---|---|
| `/pipboy` | любой | показывает свою маску, найденные устройства, выданное и отнятое |
| `/pipboy <игрок>` | moderator+ | то же для другого игрока |
| `/pipboy grant <игрок> <возможности…>` | moderator+ | выдать возможности, даже без устройства |
| `/pipboy revoke <игрок> <возможности…>` | moderator+ | отнять возможности, даже при наличии устройства |
| `/pipboy reset <игрок>` | moderator+ | сбросить всё выданное и отнятое: остаются только устройства |
| `/pipboy crack <игрок>` | moderator+ | разбить Pip-Boy (устройства с `"wrist": true`) |
| `/pipboy repair <игрок>` | moderator+ | починить |

`<игрок>` — имя персонажа (можно часть) или id. Выдача снимает то же самое из отнятого, и наоборот. Ответы команд на английском.

Примеры:

```
/pipboy grant Nik vats map      выдать V.A.T.S. и карту
/pipboy revoke Nik full         отключить всё
/pipboy reset Nik               вернуть как по устройствам
/pipboy Nik                     посмотреть, что у него
```

Ответ на `/pipboy`:

```
Pip-Boy Reznov: compass, map, vats
Devices: Компас; granted: map, vats; revoked: none
```

### В консоли сервера

| Команда | Что делает |
|---|---|
| `pipboy` | показывает настройки и маски всех игроков в сети |
| `pipboy reload` | перечитывает `pipboy.json` и пересчитывает маски |

## Трещина

- От взрыва: если `crackOnBlastDamage` больше 0, взрыв с уроном не ниже порога трескает носимое устройство с `"wrist": true`. Считаются взрывы и от игроков, и от NPC. Игрок получает сообщение, в логе появляется `pipboy: <username>'s … cracked by a blast of N`.
- Вручную: `/pipboy crack <игрок>`.
- Починка только `/pipboy repair <игрок>`. Ремонта предметом пока нет.
- Трещина сохраняется в базе и остаётся после перезахода.

FMP не сообщает, в какую часть тела пришёлся удар и был ли это ЭМИ, поэтому трещину от удара в левую руку или от ЭМИ сделать нельзя.

## Что видит игрок

| Ситуация | В игре |
|---|---|
| Нет `compass`, `geiger`, `biomonitor` | при `"hideHud": true` через секунду после входа пропадает весь HUD: шкалы, компас, прицел, уведомления; при `false` HUD как обычно |
| Жмёт Tab или Q много раз подряд | меню закрывается каждый раз (проверка раз в 100 мс), сообщение не чаще раза в 2 секунды |
| Нет `vats`, нажал Q | V.A.T.S. открывается и сразу закрывается, сверху «Недоступно: нужно устройство (vats)» |
| Строгий режим, нет экранов, нажал Tab | Pip-Boy сразу закрывается, сверху «Нет Pip-Boy» или «Pip-Boy треснул» |
| Возможность вернули | HUD появляется примерно через секунду после команды или после того, как подобрал устройство (до 10 секунд, если предмет выдал скрипт) |

## Чего нет и почему

FMP 0.2.5 не даёт скриптам доступа к интерфейсу игры (Scaleform), к вводу и к модели персонажа. Поэтому из исходной спецификации нельзя сделать:

| Требование | Почему нет |
|---|---|
| Скрывать отдельные шкалы HUD (только здоровье, только компас) | HUD скрывается только целиком; поэтому по умолчанию он не скрывается вовсе (`hideHud: false`) |
| Закрыть отдельные вкладки Pip-Boy (оставить только INV) | вкладками управлять нельзя; есть только «весь Pip-Boy или ничего» (`strictPipboyMenu`) |
| Блокировать фонарик (зажатый Tab) | ввод не перехватить |
| Прятать метку игрока на карте, точки врагов на компасе | нет доступа |
| Глушить щелчки счётчика Гейгера | нет доступа |
| Менять модель Pip-Boy на руке (слот 43) | нет доступа |
| Модули на C++ (CommonLibF4/F4SE) и Papyrus | ресурсы FMP — JavaScript; плагин F4SE пришлось бы ставить каждому игроку вручную, совместимость с клиентом FMP неизвестна |

**Защита от обхода.** Маску считает только сервер по своей записи инвентаря и по базе, подделать её из игры нельзя. Но HUD прячет и меню закрывает клиентский скрипт, и изменённый клиент может этого не делать. Сервер этого не заметит: открытие меню он не видит.

## Логи

**Сервер:**

| Строка | Значит |
|---|---|
| `pipboy: on; N device(s): …; without one: …; crack on blasts of …` | настройки при старте и после `pipboy reload` |
| `pipboy: <username> -> <возможности> (<причина>)` | маска игрока изменилась; причина: `login`, `inventory`, `config reloaded`, `<кто> granted …` и т. д. |
| `pipboy: <username>'s … cracked by a blast of N` | трещина от взрыва |
| `pipboy.json: …` | ошибка в настройках |
| `pipboy: pipboy.json not read (…); the module is off` | файл не прочитан, модуль выключен |

**Клиент** (`client\logs\FMP.log`):

| Строка | Значит |
|---|---|
| `[pipboy] compass, map` / `[pipboy] off` | какую маску получил клиент |
| `[pipboy] menu opened: <имя>` | первое открытие меню за сессию; по этим строкам ищут имена для `blockedMenus` |
| `[pipboy] <меню> closed: …` | меню закрыто модулем |

## Как проверить

Нужен ранг moderator или выше: в консоли сервера `setadmin <username> moderator`.

**Без игры:** при старте сервера в логе `database fmp-data/gamemode.sqlite at schema 6` и `pipboy: on; 1 device(s): Pip-Boy 3000 Mk IV [full]; …`.

**В игре:**
1. Войди и набери `/pipboy`. **Ожидается:** строка `Devices: …`.
   - `Devices: Pip-Boy 3000 Mk IV`: сервер видит Pip-Boy, всё доступно.
   - `Devices: none`: Pip-Boy в серверной записи нет, V.A.T.S. не открывается. Если так у всех, а это не то, чего ты хочешь, поставь `noDeviceMask` или выключи модуль.
2. `/pipboy revoke <игрок> vats`. **Ожидается:** Q открывает и сразу закрывает V.A.T.S., сверху «Недоступно…».
3. Без `vats` нажми Q много раз подряд. **Ожидается:** V.A.T.S. каждый раз закрывается.
4. `/pipboy reset <игрок>`. **Ожидается:** V.A.T.S. вернулся.
5. `/pipboy crack <игрок>`, потом `/pipboy repair <игрок>`. **Ожидается:** сообщения в чате, V.A.T.S. закрыт и снова открыт.
   С `"hideHud": true` и `strictPipboyMenu` то же самое проверяется для HUD и Tab.
6. `/pipboy revoke <игрок> vats` и перезайди. **Ожидается:** V.A.T.S. всё ещё закрыт.
7. Для голозаписей: открой голозапись, найди в `FMP.log` строку `[pipboy] menu opened: …` и впиши это имя в `blockedMenus` с `"holotape"`.

## Если что-то не так

| Проблема | Что делать |
|---|---|
| У всех пропал HUD | включён `"hideHud": true`, а сервер не видит Pip-Boy в инвентаре (`/pipboy` → `Devices: none`). Поставь `"hideHud": false`, затем `pipboy reload` |
| Pip-Boy или V.A.T.S. открывается при частых нажатиях | у игрока старая версия клиентского скрипта: `ensure fmp-gamemode` и перезаход |
| Камера «витает» вокруг игрока после входа | проверяется: поставь `"enabled": false`, `pipboy reload`, перезайди. Если прошло, пришли строки `[pipboy]` и `[life]` из `FMP.log` |
| Изменил `pipboy.json`, ничего не поменялось | не ввёл `pipboy reload`, или в файле ошибка (строки `pipboy.json: …` в логе) |
| Команды `/pipboy grant …` показывают только свою маску | нет ранга moderator |
| Меню не закрывается | имя в `blockedMenus` не то: сверь с `[pipboy] menu opened: …` в `FMP.log` |
